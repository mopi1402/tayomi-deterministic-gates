Gate catalog

The gates worth copying into a repo. Nothing here runs by itself: the engine reads only the repo's .gates.json. Copy the definition of a gate there, install what it requires, and adapt its files to the layout of the repo.

Generated from catalog/*.json by pnpm catalog: edit those files, never this page.

Go

Gates for a Go module. The toolchain comes from the PATH. The first build of a cold cache is slow, which is why these gates allow 60 seconds.

go/build

Builds every package of the module.

Runs
go build ./...
When the turn changes
(\.go|(^|/)go\.(mod|sum))$
Requires
  • go: https://go.dev/doc/install
Definition to copy into .gates.json
{
  "name": "build",
  "severity": "error",
  "files": "(\\.go|(^|/)go\\.(mod|sum))$",
  "run": [
    "go",
    "build",
    "./..."
  ],
  "timeoutSeconds": 60
}

go/format

Fails on the files the turn left unformatted. gofmt -l lists them and exits with 0, so the gate compares its list with the one as the turn started.

Runs
gofmt -l .
When the turn changes
\.go$
Fails on
only the output lines the turn added
Requires
  • gofmt: comes with Go: https://go.dev/doc/install
Definition to copy into .gates.json
{
  "name": "format",
  "severity": "error",
  "files": "\\.go$",
  "run": [
    "gofmt",
    "-l",
    "."
  ],
  "compare": "turn-start"
}

      TypeScript

      Gates for a TypeScript or JavaScript repo. Each tool comes from the repo's node_modules, so its version is the one the lockfile pins.

      typescript/lint

      Lints the changed files with ESLint, warnings included: a warning nobody is sent back for is never fixed.

      Runs
      eslint --max-warnings 0 --no-warn-ignored {files}
      When the turn changes
      \.(ts|tsx|js|mjs)$
      Requires
      • eslint: npm install --save-dev eslint
      Definition to copy into .gates.json
      {
  "name": "lint",
  "severity": "error",
  "files": "\\.(ts|tsx|js|mjs)$",
  "run": [
    "eslint",
    "--max-warnings",
    "0",
    "--no-warn-ignored",
    "{files}"
  ]
}

      typescript/typecheck

      Type-checks the project with tsc, since a change in one file can break the types of another. Incremental: tsc keeps what it learnt under node_modules/.cache and re-checks only what the changed files reach.

      Runs
      typescript --pretty false --incremental --tsBuildInfoFile node_modules/.cache/gates/tsbuildinfo
      When the turn changes
      (\.(ts|tsx)|^tsconfig\.json)$
      Requires
      • typescript: npm install --save-dev typescript
      Definition to copy into .gates.json
      {
  "name": "typecheck",
  "severity": "error",
  "files": "(\\.(ts|tsx)|^tsconfig\\.json)$",
  "run": [
    "typescript",
    "--pretty",
    "false",
    "--incremental",
    "--tsBuildInfoFile",
    "node_modules/.cache/gates/tsbuildinfo"
  ]
}
