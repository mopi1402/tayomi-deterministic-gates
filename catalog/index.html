Gate catalog

The gates worth copying into a repo. Nothing here runs by itself: the engine reads only the repo's .gates.json. Copy the definition of a gate there, install what it requires, and adapt its files to the layout of the repo.

Generated from catalog/*.json by pnpm catalog: edit those files, never this page.

Angular

Gates for an Angular project tested with Vitest through the Angular builder, ng test. Each tool comes from the repo's node_modules, so its version is the one the lockfile pins.

angular/tests

Runs the unit tests in a watch kept warm between turns, since ng test builds the whole application before a single test runs. At the stop, it waits for the watch to finish with the turn's changes, then fails on a build that does not compile, and on every red spec, the ones the change did not rerun included. The whole check runs ng test once, without a watch. The watch is asked for a cycle through tsconfig.spec.json, and starts again when a spec is created or deleted, since ng test lists its specs once. Angular 21 does not rebuild for a tsconfig: give its watch.sync a spec.

Runs
@angular/cli test --watch=false
When the turn changes
\.(ts|html|css)$
Requires
  • @angular/cli: npm install --save-dev @angular/cli
  • @angular/build: npm install --save-dev @angular/build
  • vitest: npm install --save-dev vitest
Definition to copy into .gates.json
{
  "name": "tests",
  "severity": "error",
  "files": "\\.(ts|html|css)$",
  "run": [
    "@angular/cli",
    "test",
    "--watch=false"
  ],
  "watch": {
    "run": [
      "{engine}/src/helpers/angular-watch.ts"
    ],
    "cycleStart": "Changes detected\\. Rebuilding",
    "cycleEnd": "Test run finished with success|bundle generation failed",
    "failed": "^FAIL |bundle generation failed",
    "sync": "tsconfig.spec.json",
    "frozen": "\\.spec\\.ts$"
  }
}

angular/build

Builds the application in a watch kept warm between turns, which type-checks every template, the ones of a component no spec reaches included: tsc alone never reads a template. At the stop, it fails on a build that does not compile, with the file and line of each error. Built without optimization into node_modules/.cache, so the dist of the project stays as it is. The whole check builds once, without a watch. The watch is asked for a cycle through src/main.ts.

Runs
@angular/cli build --optimization=false --output-path=node_modules/.cache/gates/build
When the turn changes
\.(ts|html|css|scss|sass|less)$
Requires
  • @angular/cli: npm install --save-dev @angular/cli
  • @angular/build: npm install --save-dev @angular/build
Definition to copy into .gates.json
{
  "name": "build",
  "severity": "error",
  "files": "\\.(ts|html|css|scss|sass|less)$",
  "run": [
    "@angular/cli",
    "build",
    "--optimization=false",
    "--output-path=node_modules/.cache/gates/build"

    "run": [

angular/no-new-strict-errors

Fails on the strict errors the turn added, in the TypeScript and in the templates, never on the ones already there, for a project that turned strict options off: it compiles the application through the API of the Angular compiler, with strictTemplates and each option of TypeScript its run lists forced on top of the project's own. Add or remove an option there, written as tsc takes it: one TypeScript does not know is refused. On an Angular project, it stands for the no-new-strict-errors of the TypeScript catalog, which reads no template. The compiler stays between turns and checks again when asked, reusing what it compiled: it is asked through its tsconfig, the one of -p. The build gate checks with the project's own options. An error is not new when moved, or reported with the same message in another file the turn did not change, or on a changed line as long as its file has no more errors of its code than at the turn start. It checks tsconfig.app.json: give its -p, and its watch.sync, the tsconfig of the application.

Runs
{engine}/src/helpers/angular-errors.ts -p tsconfig.app.json --strictNullChecks --strictPropertyInitialization
When the turn changes
(\.(ts|html)|(^|/)tsconfig[^/]*\.json)$
Fails on
only the output lines the turn added
Requires
  • @angular/compiler-cli: npm install --save-dev @angular/compiler-cli
  • typescript: npm install --save-dev typescript
Definition to copy into .gates.json
{
  "name": "no-new-strict-errors",
  "severity": "error",
  "files": "(\\.(ts|html)|(^|/)tsconfig[^/]*\\.json)$",
  "run": [
    "{engine}/src/helpers/angular-errors.ts",
    "-p",
    "tsconfig.app.json",
    "--strictNullChecks",
    "--strictPropertyInitialization"
  ],
  "compare": "turn-start",
  "lineKey": "^((?<file>.+?): error (?:TS|NG)\\d+) at [^\\t]*",
  "watch": {
    "run": [
      "{engine}/src/helpers/angular-errors.ts",
      "--watch",
      "-p",
      "tsconfig.app.json",
      "--strictNullChecks",
      "--strictPropertyInitialization"
    ],
    "cycleStart": "^Type check started$",
    "cycleEnd": "^Type check done$",
    "sync": "tsconfig.app.json"
  }
}

        typescript/no-new-strict-errors

        Type-checks the project with strictNullChecks and strictPropertyInitialization on, and fails only on the errors the turn added: a project that turned them off, with more errors than it can fix at once, stops growing new ones. An error is told by its file, code and source line, since tsc prints the types of a message otherwise from one compilation to the next: one a change moves to another line is not new, nor one tsc reports with the same message in another file the turn did not change, nor one on a line the turn changed, as long as its file has no more errors of its code than at the turn start. The agent still reads the message. tsc keeps watching between turns; without the watch, it runs at each prompt and stop instead. Refused when tsconfig.json only references others, as in an Angular project, since tsc would check no file: give it -p and a tsconfig. The whole check counts every error. The watch is asked for a cycle through tsconfig.json: with -p, give its watch.sync the same tsconfig.

        Runs
        {engine}/src/helpers/type-errors.ts --strictNullChecks --strictPropertyInitialization
        When the turn changes
        (\.(ts|tsx)|^tsconfig.*\.json)$
        Fails on
        only the output lines the turn added
        Requires
        • typescript: npm install --save-dev typescript
        Definition to copy into .gates.json
        {
  "name": "no-new-strict-errors",
  "severity": "error",
  "files": "(\\.(ts|tsx)|^tsconfig.*\\.json)$",
  "run": [
    "{engine}/src/helpers/type-errors.ts",
    "--strictNullChecks",
    "--strictPropertyInitialization"
  ],
  "compare": "turn-start",
  "lineKey": "^((?<file>.+?): error TS\\d+) at [^\\t]*",
  "watch": {
    "run": [
      "{engine}/src/helpers/type-errors.ts",
      "--watch",
      "--strictNullChecks",
      "--strictPropertyInitialization"
    ],
    "cycleStart": "^Type check started$",
    "cycleEnd": "^Type check done$",
    "sync": "tsconfig.json"
  }
}
